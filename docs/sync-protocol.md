# 同步协议版本

当前同步协议为 **1.0**，客户端与服务端各自声明支持的协议。协议版本独立于根目录 `VERSION` 的应用版本、`HostSyncBundle.version` 的主机快照格式版本，以及 `v1:` / `v2:gzip:` 的密文封装版本；这些版本不能互相替代。

## 声明与握手

- 客户端常量：`lib/modules/sync/sync_protocol.dart`，当前使用 `1.0`。
- 服务端常量：`server/lib/src/api/sync_protocol.dart`，当前实现并支持 `['1.0']`。
- HTTP 请求带 `X-Remlark-Sync-Protocol: 1.0`；服务端每个数据接口均先认证，再检查协议，最后才进入业务处理。
- 每个客户端 API 会话在首次数据请求前调用 `GET /api/v1/ping`。同一会话并发入口共享握手，失败可重试；每轮同步使用新会话。直接上传和删除也必须先握手，不能先修改旧服务器再检查版本。
- 握手成功后仍逐次检查数据响应的协议头，避免把协议变化后的响应误认为上传冲突、删除成功或有效数据。

当前握手成功响应：

```http
HTTP/1.1 200 OK
Content-Type: application/json
X-Remlark-Sync-Protocol: 1.0
```

```json
{
  "ok": true,
  "time": 1790000000000,
  "protocolVersion": "1.0",
  "supportedProtocolVersions": ["1.0"]
}
```

`protocolVersion` 和响应头表示本次实际使用的协议；`supportedProtocolVersions` 表示服务端已实现的版本集合。未来支持多个版本时，服务端按请求版本处理并返回所选版本，不能把服务端默认版本当作所有请求的实际协议。

## 不兼容处理

服务端不支持请求版本时返回 **426**，包括连接检测、索引、批量下载、上传和删除；不解析同步载荷，也不修改记录：

```json
{
  "error": "unsupported_sync_protocol",
  "protocolVersion": "1.0",
  "supportedProtocolVersions": ["1.0"]
}
```

此时 `protocolVersion` 表示服务端默认协议，并非协商成功。客户端停止同步，不更新时间或标记成功；设置页显示中英文“同步协议不兼容”提示。认证失败仍按原逻辑返回 401。

版本使用精确匹配；`1`、`1.1`、空字符串或未知值都不等于 `1.0`。新增小版本也必须明确声明并实现支持，不能推测兼容。

## 历史版本与升级规则

历史客户端没有协议请求头，历史服务端没有协议响应头和握手字段。为了允许现有安装平滑升级，**缺失声明仅固定视为历史 1.0**，不能视为当前软件的协议版本；显式的空值或错误类型不会被当成历史端。

| 客户端协议 | 服务端支持 | 行为 |
| --- | --- | --- |
| 1.0 | 1.0 | 允许 |
| 1.0 | 历史未声明版本 | 按历史 1.0 允许 |
| 历史未声明版本 | 1.0 | 按历史 1.0 允许 |
| 2.0（未来） | 仅 1.0 或历史服务端 | 拒绝；不自动降级写入 |
| 1.0 或历史客户端 | 仅 2.0（未来） | 拒绝 |
| 1.0 | 2.0 服务端明确保留 1.0 实现（未来） | 使用保留的 1.0 实现 |

当前没有实现 2.0。未来升级时：

1. 为新协议实现请求、响应、路由及数据语义，并更新协议常量和兼容测试；不能只改版本字符串或往支持列表添加数字。
2. 服务端若要继续兼容旧客户端，需要保留 1.0 实现并把它列入支持集合。若新版客户端也要兼容旧服务器，需要保留可明确选用的 1.0 实现；不能让 2.0 请求直接使用 1.0 接口冒充兼容。
3. 协议常量升级为 2.0 时，历史缺失声明仍映射为 1.0，因此旧服务端无法通过 2.0 客户端的握手。
4. 若未来载荷或数据库结构变化，需另外提供数据迁移或版本转换；仅保留 HTTP 协议号不能保证加密数据可读。保持主机快照与密文封装的独立版本校验。

客户端回归在 `test/sync_protocol_test.dart`，服务端回归在 `server/test/sync_protocol_test.dart`；完整真实服务联调在 `test/sync_e2e_test.dart`。
