这是一个远程客户端工具，用flutter开发，支持windows，macos，linux平台。支持windows rdp，ssh，vnc

# 设计要求
## ssh功能部分
-  ui美观简洁，符合现代软件ui要求。ui工具功能来设计，符合使用习惯
-  可以同时对多个ssh客户端进行操作
-  可以管理ssh连接，实现自动免密登录，记住密码，也能支持通过配置密钥自动登录（可以填写用户的，也可以自己生成），这里登录有个流程需要你来设计，用户可能没有选择记住密码，那么登录的时候要弹出密码输入框，也有可能密码错误，也需要有密码输入框
-  支持jump功能，可以连续配置jump的中间服务器
-  对于不同服务器的操作系统，需要在客户端卡片上显示icon，可以区分ubuntu，readhat等等系统版本，需要工具自动探测
-  支持sftp，sftp支持浏览远程目录，上传、下载、新建目录、重命名和删除文件；传输过程提供进度反馈。
-  支持出口代理，http和socks5
-  支持服务器分组，分组查看
-  在终端界面，支持直接拖动文件进行上传，或者鼠标右键进行粘贴上传（右键弹出“复制 / 粘贴”菜单：复制在有选区时可用；剪贴板为文本时粘贴即输入，为文件时显示为“粘贴并上传”；远程程序开启鼠标上报时右键交给远程）；终端上传使用独立的上传队列，进度显示在终端底部状态栏（点击查看详情、取消或重试），不进入 SFTP 页面的传输队列
-  终端界面支持选中鼠标右键复制，也支持快捷键复制
-  有服务器端可以用来给客户端同步当前已经收藏的服务器列表，客户端可以配置同步服务器地址。这里因为可以配置同步服务器比较复杂。客户端可以看到哪些服务器已经和服务器同步了，哪些还没有，因为涉及到先后顺序，可能有的服务器已经有了，但是有的服务器比服务器最后更新时间还早，但是服务器还没有的。这里简单点，给客户端上配置的服务器增加一个唯一的uuid，然后根据uuid对应的服务器信息最后更新时间来同步就好了。但是客户端上能看到是否已经同步，也就是和服务器信息一致。至于同步服务器上没有的，客户端可以添加进去同步。客户端也可以删除同步服务器上需要同步的服务器，删除之后这台服务器就不会同步了
-  要加密保存在服务器，同步过程中也需要加密。同步可以设置自动同步频率，也可以手动同步
-  没有同步服务器，不影响客户端正常使用
-  支持配置快捷指令，用户在快捷指令列表中选择，输入就可以
-  支持批量导入导出
-  支持给服务器设置免密登录（一种快捷方式，只有当系统是macos和linus是才有这个功能，就是能让系统自己的终端也能免密登录服务器，和自己客户端免密登录功能不同，就是将公钥放到服务器上，可以做成一种特殊的快捷指令，后续可以扩展这种快捷指令，和普通快捷指令不同这个会有一系列操作，普通的暂时只支持一个字符串的输入）
-  支持ai agent，可以在设置中配置多个ai agent，并且选择使用某一个作为当前使用的ai agent。ai agent和ui的交互需要设计成interface，以便对接各种ai agent。agent先支持deepseek harness cli。 ui你可以设计一下，最好能在终端页面能和agent进行chat。
-  支持ai agent的token统计，能按天进行统计，也有模型和agent的维度。能看到当天，本周，本月的token消耗，chat的状态栏中能看到token的速度，注意这个速度要去掉首字前的时间，输入多少token和输出多少token，上下文多少token。
-  支持查看agent chat记录，删除记录
-  其他必要的功能需要帮我补充添加一下

## Windows rdp/VNC功能部分

-  支持复制粘贴功能，外部复制，可以去rdp里面粘贴，里面复制可以在外面粘贴（字符串或者文件都可以）
-  支持将文件拖进rdp窗口进行传输

# 实现设计（开发补充）

## 架构
- Flutter 桌面应用，状态管理使用 provider + ChangeNotifier，依赖集中在 `lib/app/app_services.dart`。
- 数据库使用 drift ORM（SQLite），所有表的查询列都建立了索引；密码、私钥、API Key 用本地主密钥（应用数据目录下 `master.key`，权限 600）做 AES-256-GCM 加密后存储。
- 模块划分见 `docs/design-steps.md`。跨平台差异通过接口隔离：`RdpLauncher`（Windows / FreeRDP 两个实现）、`SshInteraction`（连接过程中的用户交互）、`AiAgent`（各类 Agent）、`SnippetAction`（快捷指令动作）。

## SSH 登录流程
1. 解析跳板链（检测循环与缺失），第一跳使用自身代理配置（没有则使用目标主机的代理），后续每一跳通过上一跳的 `direct-tcpip` 通道连接。
2. 每一跳独立认证：
   - 密码认证：有保存的密码直接使用；没有则弹出密码框（可勾选“记住密码”）；密码错误时再次弹框并提示“密码错误”，最多 5 次；登录成功且勾选记住时才保存。
   - 密钥认证：加载密钥（加密私钥未保存口令时弹框输入口令，口令错误可重试）；服务器拒绝密钥时自动回退为密码输入，并提示“服务器拒绝了密钥”。
   - keyboard-interactive：提示为密码且已知密码时自动应答，否则逐项弹框。
3. 主机指纹：首次连接自动记录（accept-new），之后指纹变化时弹出警告，由用户决定是否信任。
4. 连接成功后后台执行 `uname` + `/etc/os-release` 探测系统，写入主机信息，卡片显示对应系统图标。
   - 系统标识与图标统一由 `utils/os_registry.dart` 管理，读取 `/etc/os-release` 失败时回退 `/usr/lib/os-release`；优先识别 ID，再按 ID_LIKE 中完整标识的声明顺序回退。
   - 系统 Logo 存放在 `assets/os_icons/`，每个系统一张 256×256 透明 PNG，统一浅色底板，兼容深浅主题；默认 Logo 内容最大边长 208px，Windows 方形 Logo 单独使用 176px，增加四周留白；来源与原图 SHA-256 记录在 `sources.json`，保留上游许可证。`tools/generate_os_icons.py` 可重新生成（Pillow、resvg-py）。探测到的系统优先于协议默认值，只有未探测到系统的 RDP 主机默认显示 Windows；未知系统保留通用图标。

## 应用退出
- 退出（Dock 退出、⌘Q、关闭最后一个窗口）经 `AppLifecycleListener.onExitRequested` 先调用 `AppServices.shutdown()`：停止自动同步 → 关闭所有会话（SSH / VNC / RDP / SFTP）→ 结束 dsh、Codex 子进程 → 关闭数据库，然后才允许退出。数据库必须在引擎关闭前关闭，否则后台 isolate 销毁时 sqlite 清理回调访问已释放的连接导致崩溃。每步限时 3 秒，失败只记日志。

## 同步协议
- 服务端（`server/`，Dart shelf + drift）按访问令牌划分数据空间，存储 `(uuid, updatedAt, deleted, payload)`；payload 为客户端用“同步口令”经 PBKDF2 派生密钥后 AES-GCM 加密的密文，服务端无法解密；建议通过 `--cert/--key` 或反向代理启用 HTTPS。
- 客户端主机有 `syncEnabled` 与 `syncedAt`：`syncedAt == updatedAt` 为“已同步”，否则为“待同步”，未参与同步为“仅本地”。
- 同步：本地新则上传（服务器上更新时返回 409，改为拉取），服务器新则下载；服务器有而本地没有的主机自动拉取；从服务器删除后留下删除标记，其他客户端将其改为“仅本地”。
- 支持自动同步间隔与手动同步；未配置同步服务器不影响任何功能。

## AI Agent
- `AiAgent.send()` 返回事件流：文本增量、推理增量、token 用量、外部会话 id、错误。UI 只依赖事件流。
- Agent 运行环境：需要在本机安装程序的 Agent 实现 `AgentRuntime` 接口（`modules/ai/runtime/`：安装状态、版本、进度、安装 / 更新 / 移除），在 `AgentRuntimes` 中按 Agent 类型注册；界面只依赖该接口，新增此类 Agent 时不改界面。
  - 添加 / 编辑 Agent 时选择需要运行环境的类型，框内显示运行环境状态：未安装则提示并提供「安装」，安装完成前不能保存；已安装时提供「更新」或「检查更新」。
  - 检测更新只在编辑框中进行（打开时按 30 分钟缓存自动检测，「检查更新」强制检测）；Agent 列表只读取本机安装状态、不联网，副标题显示「未安装」「正在安装」；删除使用某运行环境的最后一个 Agent 时，可勾选「同时移除」（默认不勾选）。
- DeepSeek Harness（dsh）：第一个运行环境实现（`DshRuntimeController`），由应用安装、更新、移除，不依赖也不修改本机的 node / npm / dsh。
  - 安装（`modules/ai/dsh/dsh_installer.dart`）：dsh 只以 npm 包 `@deepseek-ai/dsh` 发布，先从 nodejs.org 下载最新 LTS 的 Node.js 官方包（按 SHASUMS256.txt 校验），再用这个 Node 自带的 npm 安装 dsh；先装到临时目录并运行 `dsh --version` 验证，再整目录替换，失败或中断不破坏已安装版本。Node 只在缺失或主版本落后最新 LTS 时重装。
  - 目录（应用数据目录下 `dsh/`）：`node`（Node.js）、`runtime`（dsh 及依赖，约 1GB）、`home`（DSH_HOME：profile 与会话记录，升级和移除运行环境时保留）、`workspace`（会话工作目录，空目录）。
  - 平台差异（安装包名、node/npm 路径）由 `DshPlatform` 接口封装，macOS / Linux / Windows 各自实现；解压使用公共的 `utils/archive/ArchiveExtractor`（同样按平台实现：系统 tar / unzip，Windows 用 System32 的 bsdtar）。
  - 运行（`dsh_acp_service.dart`）：`node <dsh 入口> --profile acp` 常驻子进程，标准输入输出上走 ACP（Agent Client Protocol，JSON-RPC 2.0，每行一条消息，连接为 dsh 与 Codex 共用的 `runtime/json_rpc_connection.dart`）。首次提问时启动，所有聊天共用；每个 API Key 一个进程（以 `DEEPSEEK_API_KEY` 环境变量传入）；进程退出后下次提问自动重启；安装或升级前结束进程。
  - 会话：每个聊天一个 dsh 会话（`session/new`，会话 id 存为聊天的外部会话 id）；同一进程中直接 `session/prompt` 续问；进程重启后 `session/resume`；恢复失败时新建会话，第一条消息附上之前的对话。配置了模型时按名称匹配会话公布的模型选项并 `session/set_config_option`。
  - 提问结束后继续接收迟到的更新（300ms 内无新更新才结束本轮，还没有回答文本时最多等 5 秒），防止 dsh 偶发先返回结束、后送达最后一条消息时丢失回答；迟到的更新会写日志。
  - 输出：`agent_message_chunk` 为回答，`agent_thought_chunk` 与工具调用标题显示在推理区，`usage_update` 提供上下文占用；dsh 不报告每轮输入 / 输出 token，按文本估算并标注“≈”。
  - 不碰用户的电脑：启动时附加补丁（`DSH_HOME/remlark.patch.yml`）关闭 dsh 的全部自带工具（bash / pwsh / 文件读写与搜索 / jobs / workflow / 子 Agent / 切换目录，以及网络搜索与抓取 / todo / goal / skill / 计划模式，避免模型浪费轮次），dsh 自身的权限请求一律拒绝，不声明文件系统与终端能力；dsh 只负责思考下一步，命令由 Remlark 输入到用户的终端。
- Codex：第二个运行环境实现（`CodexRuntimeController`，`modules/ai/codex/`），参照 GitAstra 的接入方式，由应用安装、更新、移除，不依赖也不修改本机的 codex 与 `~/.codex`。
  - 安装（`codex_installer.dart`）：从 GitHub Releases（`openai/codex` 最新版本）下载当前平台的完整运行包 `codex-package-<架构>-<平台>.tar.gz`（主程序、执行工具、资源，约 350MB），按发布信息中的 SHA-256 校验；解压到临时目录，运行 `codex --version`（版本须与发布一致）与执行工具 `--help` 验证后整目录替换，失败或中断不破坏已安装版本。版本从运行包的 `codex-package.json` 读取，不启动进程。最新版本查询缓存 30 分钟（GitHub 未登录接口有频率限制）。
  - 平台差异（发布包名、可执行文件名）由 `CodexPlatform` 接口封装，macOS（apple-darwin）/ Linux（musl 静态包）/ Windows（msvc，.exe）各自实现。
  - 目录（应用数据目录下 `codex/`）：`runtime`（运行包，升级时整包替换）、`homes/<Agent uuid>`（每个 Codex Agent 独立的 CODEX_HOME：登录凭据与会话记录，仅当前用户可访问，升级与移除运行环境时保留，删除 Agent 或放弃新建时删除）、`workspace`（会话工作目录，空目录，避免读取任何项目文件与 AGENTS.md）。
  - 运行（`codex_app_server.dart`）：`codex app-server --listen stdio://` 子进程，标准输入输出上走 JSON-RPC。聊天使用常驻进程（每个 Agent 一个，首次提问时启动，退出后自动重启，登录状态变化与安装升级前结束）；设置页读取账号、模型与登录使用短生命周期进程，用完即关闭。同一 CODEX_HOME 的进程启动（启动 + 握手）排队进行：多个进程同时初始化 CODEX_HOME 中的 sqlite 状态库会报 “failed to initialize sqlite state runtime”（新目录上同时读取账号与模型时必现）；握手完成后多个进程可同时运行。
  - 不碰用户的电脑：启动参数以 `-c features.<名称>=false` 关闭本机命令（shell_tool / unified_exec）、插件与应用、子 Agent、图片生成、浏览器 / 电脑操作、goals、hooks 等功能（新版本中不存在的名称只会被忽略，不会导致启动失败），`web_search="disabled"`；线程只读沙箱、从不请求审批，app-server 发来的请求一律拒绝。Codex 只负责思考下一步，命令由 Remlark 输入到用户的终端。
  - 会话（`agents/codex_agent.dart`）：每个聊天一个 Codex 线程（`thread/start`，线程 id 存为聊天的外部会话 id），系统提示词（终端操作协议）作为 `baseInstructions` 替换 Codex 默认的编程助手提示词；同一进程中直接 `turn/start` 续问；进程重启后 `thread/resume`；恢复失败时新建线程，第一条消息附上之前的对话。每轮先读取账号，未登录直接提示到设置中登录。模型与推理强度见下文。
  - 输出：`item/agentMessage/delta` 为回答（没有增量时使用 `item/completed` 的完整消息），`item/reasoning/summaryTextDelta` 显示在推理区，`thread/tokenUsage/updated` 的 `last` 累加为本轮输入 / 输出 token，上下文取最近一次调用；取消时 `turn/interrupt`。
  - 账号与模型（设置页 Agent 编辑框，`settings/ui/codex_account_panel.dart`）：打开时依次读取账号与模型（不同时启动多个进程，与 GitAstra 一致）；未登录时「登录 ChatGPT」（`account/login/start`，在系统浏览器中打开登录页，等待期间可取消或复制登录链接；与 GitAstra 相同，登录在临时 CODEX_HOME `homes/.login-*` 中进行，成功后只把 `auth.json` 替换到 Agent 的目录，取消或失败时删除临时目录，原登录不受影响），已登录显示邮箱与订阅并可退出；模型下拉框来自 `model/list`，打开编辑框时与登录完成后自动刷新，也可手动刷新，第一项为 Codex 默认模型。Codex Agent 不保存 API Key。
- 模型与推理强度：运行环境接口 `loadOptions` 读取 Agent 可选的模型（每个模型带支持的推理强度与默认值），`AgentOptionsController` 按 Agent 缓存，聊天窗口与设置页共用。
  - 聊天输入框：⌘Enter（macOS）/ Ctrl+Enter（Windows、Linux）发送，单独按 Enter 换行（避免误触发送）。终端当前屏幕（最近 30 行）在所有权限模式下自动附上，有选区时另外附带选中内容（不再有“附带终端输出”开关）。
  - 聊天窗口顶部显示当前聊天标题（新对话显示“新对话”），右侧为历史记录与新对话。输入框上方工具栏：Agent、模型、推理强度三个紧凑下拉菜单，右侧为命令权限；空间不足时优先保留 Agent 名称。Agent 在这里切换（菜单列出全部 Agent 与类型，底部「管理 Agent…」跳到设置页）；设置页只负责添加、编辑、删除 Agent，不再选择当前使用的 Agent。
  - 聊天绑定 Agent：聊天有消息后固定使用开始时的 Agent（`ChatController.boundAgentUuid`，来自会话记录的 agentUuid）；切换 Agent 时设为以后新聊天的默认，当前聊天已有消息则新建对话（换 Agent 无法续用原上下文与提示词缓存）。其他终端标签中的聊天不受影响，继续使用各自的 Agent。模型与推理强度选择结果保存到该 Agent 的配置（`model`、`reasoningEffort`，数据库 schema 2 新增 `reasoning_effort` 列），每个 Agent 各自记住；切换 Agent 即切换到它的模型与推理强度。第一项为「默认（X）」；切换模型时新模型不支持当前推理强度则改回默认；模型菜单底部可刷新列表；回答进行中不能切换。
  - dsh：可选项来自会话公布的 ACP 配置项（模型 category=model，推理强度 category=thought_level：off / low / high / max，默认 high），每个 API Key 新建一个会话读取一次并缓存；每轮提问前按配置 `session/set_config_option` 切换（聊天中途切换立即生效），配置为默认时切回该配置项的默认值。
  - Codex：可选项来自 `model/list`（每个模型支持的推理强度不同）；模型与推理强度随每轮 `turn/start` 传入。Codex 编辑框中也可选择模型与推理强度；登录或退出后丢弃缓存。
  - OpenAI 兼容 API：模型来自接口的 `GET /models`（`agents/openai_models.dart`，带 API Key 时 Bearer 认证，本地服务如 Ollama 可不填）；没有默认接口地址与默认模型（不再默认 DeepSeek）：必须填写 API 地址并选择模型才能保存，未配置时提问直接提示；推理强度固定为默认、不可选择。界面统一称“OpenAI 兼容 API”（`AgentKind.label`）。设置页模型输入框右侧「获取列表」读取后在下方弹出选择，也可直接输入；API Key 输入框可切换显示。
  - 运行环境未安装的 dsh / Codex 只显示配置的模型。
- 运行环境接口另有 `removeAgentData`：删除 Agent 或放弃新建时清理该 Agent 在运行环境中的专属数据（Codex 的 CODEX_HOME；dsh 无专属数据）。聊天续接外部会话按 `AgentKind.keepsContext` 判断（dsh、Codex）。
- AI 操作终端（`modules/ai/terminal_agent/`，与具体 Agent 无关，Codex、OpenAI 兼容 API 同样适用）：
  - JSON 协议（`terminal_agent_protocol.dart`）：系统提示词约定 Agent 每轮只回复一个 JSON 动作——`run`（一条命令 + 本步说明）、`wait`（命令还在运行，N 秒后再看，2–300）、`answer`（在聊天中回答，任务结束）。回复不是合法动作时整段作为回答，普通问题直接 `answer`。
  - 循环（`ChatController.send`）：用户提问附上终端当前屏幕 → Agent 回复动作 → 执行 → 把终端新增输出（`AnsiUtils` 去掉控制序列、处理 `\r` 进度覆盖，超长保留末尾 12000 字符）作为下一轮提问 → 直到 `answer`。每一步都是一次独立提问，命令执行多久都可以；单次任务最多 200 步。没有收到回复时请 AI 重新回复一次，仍没有则在聊天中提示，任务不会悄悄结束。
  - 上下文：同一个聊天（直到「新对话」）的所有步骤与提问共享上下文。dsh 全部发到同一个 dsh 会话，由 dsh 保存；不保存上下文的 Agent（OpenAI 兼容 API）每一步都重新带上整个对话：用户问题、AI 的原始 JSON 回复（界面显示整理后的文字）、终端输出。
  - 执行（`terminal_step_runner.dart`）：命令直接写入该终端会话的 shell（不经过广播；shell 开启 bracketed paste 时按粘贴发送）。从任务开始持续记录终端输出，每次汇报「上次汇报之后的新输出」，Agent 思考期间的输出也不丢。执行后输出停顿 2 秒（最长 20 秒）汇报；`wait` 期间有新输出后停顿 5 秒提前汇报。命令是否结束、是否成功由 Agent 判断。
  - 终端由用户自己控制：AI 操作期间不限制用户输入；命令卡住等输入（密码、确认）时由用户在终端里输入。停止只结束 AI 的后续步骤，已在终端运行的命令不受影响。
  - 聊天显示：每一步显示说明与命令代码块，交给 AI 的终端输出显示为可展开的「终端输出 · N 行」，最后显示 `answer` 的回答（Markdown）；推理过程照常显示。终端输出以 `terminal` 角色保存在聊天记录中，会话无法恢复时作为用户消息交给 Agent。
  - 权限（聊天底部「附带终端输出」旁的选择器，每个终端标签页独立，新标签默认逐条确认）：
    - 只给建议：不操作终端，普通流式对话，命令由用户一键发送到终端；
    - 逐条确认：命令填入终端但不回车，聊天显示「检查后在终端按回车执行，按 Ctrl+C 放弃」；用户按回车（可先修改）后继续，按 Ctrl+C 则告知 Agent 未执行；
    - 只读自动执行：`ReadOnlyCommands` 判断为只读的命令直接回车（白名单 + 子命令限制，禁止重定向、命令替换、后台执行、sudo，按管道 / && / ; 拆分逐段判断，无法确定的视为非只读），其他命令同逐条确认；
    - 全部自动执行：直接回车，选择器以警示色显示。
    - 在「只给建议」与操作终端之间切换时，续聊的本轮提问前附上说明告知 Agent（系统提示词只在新会话发送）。
- 每个终端标签页一个聊天：切换标签页回来继续原对话（新对话需手动新建）；系统提示词中的服务器即该终端的服务器；在其他服务器的终端里载入历史记录时不续用原 dsh 会话，而是新建会话（并附上之前的对话），也不改写原记录。
- OpenAI 兼容 API（默认 DeepSeek API）：SSE 流式，`stream_options.include_usage` 获取用量。
- 速度 = 输出 token / (结束时间 − 首个 token 时间)，不包含首字前等待；同时显示输入、输出、上下文 token 与首字延迟。Agent 未上报用量时按字符估算并以“≈”标注。
- 每次请求写入 token 明细（按日期键索引），统计页按今日 / 本周 / 本月汇总，并按模型、按 Agent 聚合；聊天记录可查看、续聊、删除。

## 远程桌面
- RDP：内嵌 FreeRDP 3（native/rdp，静态链接 OpenSSL，C 胶水库经 Dart FFI 调用，画面在应用内标签页渲染）。
- SSH 加密：dartssh2 使用内置副本（third_party/dartssh2，仅补丁 AES-GCM 后端可注入），AES-GCM 由原生库 native/ssh_crypto（静态链接 OpenSSL，硬件 AES 指令）经 Dart FFI 计算；原生库缺失时退回纯 Dart 加密并优先 chacha20-poly1305。SFTP 读写请求 64KB，传输进度通知限频 100ms。
  - 登录：保存的密码直接登录；未保存则弹框（可记住）；用户名或密码错误时重新弹框。
  - 证书：首次连接记录 SHA-256 指纹，之后指纹变化时警告并由用户决定是否信任。
  - 显示：GDI 合成 BGRA 画面；未设置固定分辨率时，远程分辨率随窗口大小动态调整（Display Control 通道）。
  - 剪贴板：文本双向；本地复制的文件 / 目录可在远程粘贴（远程按需读取内容）；远程复制的文件下载到本地后写入系统剪贴板，可在本地粘贴。
  - 文件拖拽：拖入 RDP 画面的文件放入共享文件夹（远程 \\tsclient\Remlark）并写入远程剪贴板；服务端确认后在松手处单击激活窗口并发送 Ctrl+V，直接粘贴到松手处的文件夹或桌面。
  - 支持 HTTP / SOCKS5 出口代理；macOS 上 Command 键映射为 Ctrl，工具栏提供 Ctrl+Alt+Del 与 Windows 键。
- VNC：内置 RFB 3.3/3.7/3.8 客户端（None / VNC / Apple Remote Desktop 认证，Raw、CopyRect、ZRLE 编码，DesktopSize 与 Cursor 伪编码），键鼠转发，剪贴板双向同步。
  - 渲染（多线程流水线）：后台 isolate 负责网络、协议、解码与更新合并，按变化区域零拷贝转给 UI；UI 只调度；引擎在 GPU 上把区域覆盖到上一帧并渲染。线程间消息队列通信，同一时刻最多 1 帧在途（背压），每次更新整体替换避免撕裂；指针由本地绘制。
  - 配置：主协议只提供 SSH、VNC、RDP。VNC 选项内通过“启用 SSH”开关显示 SSH 配置；开启后同一台主机即可单独连接 SSH 或 VNC，关闭后只保留 VNC 入口。两种连接共用一条主机记录、地址、用户名和密码，分别设置端口，SSH 支持密码/密钥/键盘交互认证及跳板/代理。卡片与列表将 SSH、VNC 显示为两个独立协议色标签，间距 6px。卡片、列表、右键菜单提供 SSH 终端与 VNC 桌面两个独立连接入口；卡片使用 40px 圆形图标按钮、间距 8px，SSH 为终端图标，VNC 为桌面图标，均使用实心强调色背景；悬停/聚焦叠加 12% 前景色、按下叠加 20% 前景色，单协议与多协议使用相同的协议图标按钮：SSH 为终端，VNC/RDP 为桌面，不再使用连接箭头，列表缩为 32px；悬停及无障碍名称使用中英文连接说明；两个协议筛选均包含该主机，工作区选择器按连接方式列出，广播可使用其中 SSH。单独 VNC 不提供快捷文件传输。VNC 画面直接经 RFB 连接，SSH 不作为画面隧道。
  - 兼容：旧关联仅在地址、账户、凭据及网络设置可无损合并时迁移；其他旧关联保留，用户主动启用内置 SSH 时替换。
  - 剪贴板（启用 SSH，远程为 macOS）：文本与文件双向复制粘贴。
    - 本地复制文件后在 VNC 中按 ⌘V：远程最前为 Finder 时直接上传到 Finder 插入位置（顶层窗口或桌面，同名改名）；其他应用经远程缓存目录写入远程剪贴板后补发 ⌘V。
    - 在 VNC 中复制（⌘C / ⌘X 或离开应用时检测）：文件在本地剪贴板放入延迟占位项（macOS），在本地粘贴时才下载，由本地 Finder 放到其顶层窗口或桌面；其他平台复制即下载；文本直接同步。
    - 文本同时发送标准 RFB 剪贴板消息，兼容其他 VNC 服务端。关闭 SSH 后仍有画面、键鼠和服务端支持的标准文本剪贴板，但无文件传输、增强文本/文件复制粘贴、Finder 定位及锁屏检测。
  - 拖拽上传：经内置 SSH（兼容旧关联）上传；远程为 macOS 时由辅助小程序 RemlarkFinder 查询 Finder 窗口布局，按松手位置传到对应 Finder 窗口文件夹（无窗口为桌面），无法识别时提示原因不上传；非 macOS 传到主目录。
- VNC 与 RDP 共用 RemoteScreen 渲染组件（会话实现 RemoteDisplay 接口）。

### 最小窗口下的远程工具栏

- RDP 工具栏可用宽度不足 780 时收起按钮文字，保留原操作位置与中英文提示，避免英文界面在 960×640 窗口下溢出；宽窗口仍显示文字。

## Windows 安装与分发

- 开发运行提供 `windows/run.ps1`，普通 PowerShell 中无须安装 Make；缺少原生库时初始化 VS x64 环境并构建，已有库时直接运行，修改原生代码后用 `-RebuildNative`。

- `make windows` / Windows 下 `make` 生成版本化的 Inno Setup 安装向导 `.exe` 和便携 zip；安装器源文件集中在 `windows/packaging/`。
- 默认安装到当前用户的 `%LOCALAPPDATA%\Programs\Remlark`，中英文向导、开始菜单入口、可选桌面快捷方式；固定 AppId 支持覆盖升级，卸载保留用户数据库、凭据与日志。
- 安装器和便携包附带应用本地 VC++ 运行库；打包前检查 Flutter 引擎、RDP / 加密 / sqlite DLL 与 AOT 资源，阻止缺项分发。
- 工具链和使用方法见 [build-environment.md](build-environment.md)。

## 运行日志
- 日志重新初始化时先关闭旧文件；`AppLog.close()` 刷新并释放文件句柄，确保 Windows 下可以删除或切换日志目录。
- `<数据目录>/logs/remlark-yyyy-MM-dd.log`，按天切分、保留 7 天；设置 → 数据 可打开日志文件夹。
- 关键流程（连接、认证、上传、同步、异常）均记录日志，以便从日志定位问题；不记录密码、私钥、口令。
- 远程桌面会话不提供 AI Agent 功能。

## 2026-10-20 UI 重设计（已实施，见 design-steps Step 20~22）

### 设计目标与边界

- 按功能重新组织界面，不沿用现有 Material 默认布局。目标为克制、精确、适合长期使用的桌面远程工具。
- 相同结构的弹窗复用统一模板。
- 布局统一为：所有一级页面同一页头（标题 + 副标题 + 右侧主要操作），二级导航（主机分组、设置分区）统一在页头下方左侧；工作区打开会话后页头收缩为一行以最大化内容区。界面以本节规范、现有业务逻辑和本地化资源为准。

### 信息架构

保留主机、工作区、快捷指令、密钥、AI、设置六个主入口。固定应用导航宽 196 逻辑像素；工作区采用紧凑顶部标签。设置增加通用、终端、同步、AI Agent、数据的分区导航，替代整页长表单。主机编辑采用分区导航和固定底部操作栏。

**SFTP 调整为独立工作区 Tab**，不再作为终端右侧面板。左侧是本地文件系统，右侧是当前 SSH 主机的远程文件系统；两侧独立地址栏、前进/返回/上级目录、刷新、列表选择。下方共享可折叠传输队列，显示来源、目标、上传/下载方向、进度、速度、失败与重试。终端“打开 SFTP”打开或激活该 SSH 会话关联的 SFTP Tab，保留当前目录与队列状态，切换 Tab 不关闭 SSH 连接。跨侧拖放进行上传/下载；同侧操作不得被误判为跨侧传输。已实现（Step 21）。

终端保留可伸缩 AI 侧栏。AI 命令“插入终端”只填入命令，不自动执行。工作区采用第三版“紧凑右侧工具组”：顶部保持单行标题、可横向滚动的会话标签与“新建会话”；最右侧独立显示广播、布局入口。仅有 VNC/RDP 时隐藏广播，有 SSH 时允许选择广播目标。布局菜单提供单窗口、网格、选择参与会话，普通网格最多显示 9 个 SSH/VNC/RDP 会话，输入保持独立，SFTP 不参与网格。双击格子标题栏或点击放大图标可聚焦该会话，点击“返回网格”恢复原选择；画布内部的双击继续交给远端或终端选词。切换采用同一会话视图树，保留连接与界面状态。广播只向显式选择的 SSH 目标同步输入，新增会话不自动参与；广播期间不论当前选择单窗口还是网格，画布固定以网格展示全部广播目标（标签栏只能在目标之间切换输入焦点，新开会话在后台打开）；同一顶部行显示警示色目标数量与停止按钮，禁用布局和格子放大，停止后恢复广播前的布局。网格中收起各会话工具栏、状态栏和 AI 面板，聚焦后恢复完整操作。RDP/VNC 使用完整远程画布，保留各自剪贴板/传输能力，不提供 AI 控件。

### 弹窗复用与行为约束

- 新建/编辑同一种对象复用对应编辑图：仅标题、默认值、主要按钮文案变化。编辑现有主机时协议不可切换。
- 新建分组/重命名分组复用 24；新建目录/重命名文件复用 36；目标名称与原始值必须准确，不因复用改变业务行为。
- 删除分组、密钥、快捷指令、Agent、聊天记录、远程文件复用 25 的确认布局，明确实际后果。删除远程文件须展示远程主机及路径；不要使用“不会删除远程数据”的主机专属说明。
- 主机删除若已参与同步且服务端已配置，使用 42，保留“同时从同步服务器删除”选项；不得省略为普通删除框。退出同步使用 43，本地主机保留为仅本地。
- 密码错误、私钥口令错误、密钥被拒后回退密码均使用对应认证模板的行内错误区。RDP 登录复用密码框并显示准确协议；RDP 证书变化复用 23 的身份核验布局与证书字段。
- JSON 导入与 SSH Config 导入使用系统原生文件选择器；导出使用系统原生保存位置选择器；不重画或实现自定义操作系统文件对话框。导入结果、复制公钥、保存、同步成功与失败使用统一轻提示。
- Agent 的 CLI/API 字段按类型切换，不增加业务尚不支持的参数或测试连接功能；特殊动作的执行窗口不得提供实际无法取消的按钮。
- 图中装饰性额外按钮不直接作为功能需求。实施时逐项映射现有业务动作，移除无对应动作的控件；演示文案需校对并提供双语。
